# mmd2bip — MMD 动作 → BetterPose 动作文件

把 VMD（MMD 动作）转换成本项目 BetterPose 插件能播放的 JSON 动作文件，目标骨架是该游戏角色的
3ds Max Biped 骨架（`Bip001-*`）。转换全部离线完成，游戏内只做播放。

## 流程

1. **导出骨骼**：游戏内 BetterPose 面板 → Export Skeleton，得到 `*.skeleton.json`
   （含 `baseLocal`＝捕获时的活姿势，以及 `refLocal`＝引擎参考姿态，即网格真正的绑定姿态）。
2. **解析源数据**（每个源文件只需做一次）：
   ```
   python pmx_dump.py  <model.pmx>  pmx.json     # MMD 模型：骨骼位置/尾巴/父子
   python vmd_dump.py  <motion.vmd> vmd.json     # MMD 动作：每根骨的关键帧
   ```
3. **转换**：
   ```
   python mmd2bip.py --pmx pmx.json --vmd motion.vmd --vmd-json vmd.json \
                     --skeleton pose.skeleton.json --out motion.json \
                     [--ik-mode follow|on|off] [--mapping 源轨道=目标骨]... \
                     [--parent 源轨道=目标骨]... \
                     [--parent-position 源轨道=目标骨]... \
                     [--parent-no-rotation 源轨道=目标骨]... \
                     [--parent-anchor 源轨道=目标骨=目标静止骨]... \
                     [--control 源轨道=类型,手,手指,轴,增益[,双手]]... \
                     [--arm-ik 源轨道=手,增益,最大弯曲[,双手][,跟随手腕]]...
   ```
4. **部署**：把生成的 JSON 交给插件（面板里选文件 → load → play）。

游戏内 MMD 页还提供“检查 VMD”。通用预检只解析文件名和轨道特征，不依赖当前角色骨架，
会给出推荐参考、置信度和 FK/IK、D/EX、腰取消、肩 P/C、捩骨等结果；推荐不会自动改动
当前选择，只有点击“采用推荐源骨架”才会切换。

同一份结果还会按**当前选中的参考源、当前角色骨架和手动映射**执行一次与实际转换相同的
`BuildMapping` 审计：

- 映射详情与编辑区默认隐藏在“显示映射详情与编辑”复选框中；关闭只会收起诊断与操作，
  已按角色保存的映射和忽略项仍继续生效。
- “已映射源轨道”列出每条 VMD 源轨实际接到的 `Bip001-*` 目标骨。
- “未映射轨道”只列当前这一组合下转换器不会消费的源轨。
- 切换参考源或增删手动映射时自动重新检查；参考源缺少第四指节、D/EX、指尖骨等会直接反映
  在结果中。
- 通用推荐仍只由 VMD 本身决定，因此换参考源不会改变推荐，但会改变参考源映射审计。

预检结果下方会列出未映射轨道，按人体骨、控制/辅助骨、其他、配件骨排序。每一项显示
轨道名、关键帧数和首个非零帧；最多显示前 80 项，其余显示剩余数量。人体/控制骨排在
配件骨之前，避免长发或裙骨把真正需要处理的特殊骨淹没。

未映射轨道行可直接点击“映射”，过滤并选择当前角色的目标骨。映射按角色保存，重新转换
VMD 时作为显式 `源轨道 -> 目标骨` 表追加到内置映射之后；已经自动占用同一目标骨时不会
重复写入。

选中任意已映射或未映射源轨后，可以勾选“作为父级插入”，分别选择继承旋转和位移，再选择
目标骨。父级关系会通过目标骨架层级自然带动后代。启用位移时还可以指定一个目标静止骨：
父级围绕该骨旋转，位移也会被转换到目标骨父级的 rest 坐标系并写入 `boneOffsets`。同一
源轨可以插入多个目标骨；同一目标骨的父级按插入顺序组合，后添加的一段位于外层。面板会
列出已保存的父级关系及其旋转、位移和锚点并允许单独移除。

控制模板可把源轨解释成 **握拳** 或 **张指**。面板可选择左手/右手/双手同步、
全部或单根手指、XYZ 输入轴和 `-3..3` 控制比例。转换器读取控制四元数的指定分量，
按手掌平面为目标手指链生成额外旋转；张指只驱动手指根节，握拳会按掌骨、指根和末节
权重驱动整条链。模板与直接映射、忽略项及父级关系可以同时生效。

配置区提供“启用配置预览”和“预览弯曲幅度”。进入手部控制模板后，调整手、手指、类型或
增益会立刻写入当前显示姿势并驱动目标手链；预览只用于判断方向和范围，使用合成弯曲角度，
不会修改动作 JSON。取消、添加完成、忽略、恢复自动或关闭面板后会停止预览并回到原动作。

控制源轨由名称和动作特征自动筛选。名称命中 `握/張/grip/spread/hand` 等词会标为推荐；
名称不明显时，预检还会分析四元数主轴占比和方向变化次数。无名称线索的“动作特征”候选
必须具备高单轴占比和至少一次正反向切换；单向漂移与纯位移轨不会自动混入。普通手指、
手首、捩骨以及腰肩腿等结构控制轨也不会进入候选列表。

“手臂 IK”模板把源轨局部位移换算成当前角色手腕目标偏移，并使用目标角色的
UpperArm / ForeArm / Hand 实际骨长做二骨求解。支持左右手或双手、`0.1..3` 控制比例、
`20..170°` 最大肘部弯曲，以及可选的手腕朝向跟随。不可达目标由求解器限位；手链缺失或
源轨不存在会进入映射问题。配置时可用合成手腕偏移实时预览。

映射面板同时提供“明确忽略”和“恢复自动映射”：

- “明确忽略”会覆盖同一源轨的自动映射和手动映射，当前动作不再消费该轨道。
- “恢复自动映射”同时清除该源轨的手动映射和忽略状态。
- 未解决项会区分当前参考源缺骨、当前角色缺目标骨、目标已被占用、源轨在当前 VMD
  中不存在等原因。
- 当前角色已不存在的目标骨会在下一次审计后自动清理；暂时不在当前 VMD 的映射会标成
  源轨缺失并保留，便于之后转换相近动作。

MMD 页底部的“动作 IK”紧靠在“动作参考校准”上方，提供三档：

- **跟随动作**：使用 VMD 自带的 IK 开关记录。
- **强制开启**：忽略关闭记录，解算所有受支持链。
- **强制关闭**：跳过源 IK，只播放 FK。

IK 模式是转换参数，切换后需要重新转换 VMD。

BetterPose 内置三份源骨架参考：

- `reference-pmx.json`：标准初音未来 PMX。
- `reference-miku-unity.json`：Kinsama式初音未来V4C。
- `reference-endfield-standard-a.json`：由
  `generate_endfield_standard_reference.py` 从 Endfield-Poser 的 `StandardRig`
  生成的 73 骨标准 MMD / A 姿，包含左右腿和脚尖 IK。参考数据在插件 MMD 页直接切换，
  更换后需要重新转换 VMD。

Unity V4C 的环指/小指只有 `１/２/３/先`，没有 `０`。这表示该参考模型没有 MMD 某些
四节手指动作里的基础 `０` 骨；参考源审计会如实显示这个结构差异。若当前角色目标手链更短，
转换器会按下方的合并规则保留全部源旋转。

## 映射规则

- 骨名映射表 + 手指链。比较时会把全角数字和全角拉丁字母统一成半角：例如 MMD 的
  `左人指１` 对目标 `1`，以及动作里的 `左足ＩＫ` 对 StandardRig 参考的 `左足IK`。
  不做这层归一化时，IK 控制器整条位置轨会静默丢失，表现为身体在动、腿却留在原地或横躺。
- 食指别名 `人差指` 与 `人指` 按同一根骨处理。手指末端的 `…先 / …２先 / …３先` 轨道
  会叠加到目标手链最后一节，例如 `左人差指３先` 驱动 `Bip001-L-Finger13`，不会再作为
  未映射人体轨道列出。
- 手指链不再固定只取前三节。目标手链有三节时映射前三节，有四节时会把
  `０/１/２/３`（或 `１/２/３/４`）四节全部接上；这份样本中的
  `左/右小指３` 与 `左/右薬指３` 因此会进入目标第四指节。
- 当源动作的指节数多于当前角色目标手链时，不再丢弃多出来的两端。相邻源指节会按顺序
  合并到最近的可用目标指节，例如源 `０/１/２/３` 遇到目标只有两节时会形成
  `０+１ -> 第一节`、`２+３ -> 第二节`，不会把 `０` 和 `３` 留成未映射。
- 源与目标都是四节时严格一一对应：`０/１/２/３` 分别驱动目标
  `Finger4/41/42/43`（或其他手指对应四节），不会因参考模型缺少 `０` 而改变顺序。
- 归一化只用于查找，输出和 `ReferenceBone` 查询仍使用参考文件里的**真实名称**。因此
  StandardRig 的 `左人指1`（半角）与普通 PMX 的 `左人指１`（全角）都能驱动同一组目标手指；
  旧实现会把前者误写成不存在的全角名，导致手指链静止。
- 腿标准链兼容 `足D / ひざD / 足首D / 足先EX`。参考骨架只有 D/EX 链、没有普通
  `足 / ひざ / 足首 / つま先` 时，会用 D/EX 链补全目标腿；两套都存在时继续使用普通链，
  保持 Unity Miku 参考的既有结果。
- Standard MMD / A 的 `頭` 使用竖直 `tailOffset` 定义头骨方向。`両目` 在头骨前下方，
  若拿它代替头部方向，整段动作会恒定低头约 45°；眼睛仍保留为头骨子节点，只不再决定
  头骨的 rest 轴。
- 三段式脊柱同时兼容两套命名：`上半身/上半身1/上半身2` 映射到
  `Spine/Spine1/Spine2`；没有 `上半身1`、但存在 `上半身3` 时改为
  `上半身/上半身2/上半身3`，不再丢掉上胸段动作。
- `肩P/肩C` 按 MMD 的父子取消关系映射：锁骨收到 `肩P × 肩`，上臂用逆 `肩P`
  抵消父级那一份，避免肩部控制旋转把整条手臂一起带走。
- `腕捩/手捩` 的显式源旋转会分摊到目标的上臂/前臂两根 Twist 辅助骨；源轨道不存在时
  才使用原来的肢体旋转投影作为回退。
- VMD 的模型显示关键帧按阶跃方式输出和播放，暂停或拖动时保持当前帧；卸载动作、换角色
  或开始另一份动作时恢复播放前的组件可见性，查询失败的对象会保留待恢复状态并重试。
- 腿部同时存在完整 FK（`足/ひざ/足首`）和 IK 时，优先保留误差合理的 IK；若 IK 后残留
  超过 `max(0.5, IK 前误差×35%)`，该帧自动回退到 FK。正常 Unity/StandardRig 样本
  不会触发，错配参考骨架会触发并在 IK 诊断中记录 `fallbackFrames`。
- VMD 预检按 `上半身3`、`腰キャンセル`、`D/EX`、`肩P/C` 和脊柱段数给三份参考打分。
  置信度低于“中”时会明确提示特征混合，避免把不确定的建议当成结论。
- **手指链按累计长度对齐**，不按序号：目标骨架每根手指是 **4 节**（`Finger1/11/12/13`），
  MMD 是 **3 节**（`人指１/２/３`）。按序号映射会让指尖骨完全没有轨道（症状：“第三节指尖不对”）。
  多出来的第一节（掌骨）输出为**静止轨道**（保持在 rest，跟手掌刚性延伸）。
- MMD 骨方向：默认用 PMX 尾巴，但**「被映射的子骨」优先**——因为有些骨的尾巴是标记而不是方向
  （腰的尾巴朝前，取它会把骨盆整体转 67°，上半身随之后仰、人看着变矮）。

## 开关与默认值

| 开关 | 默认 | 说明 |
| --- | --- | --- |
| `--rest-source {bind,live}` | `bind` | rest 用 `refLocal`（引擎参考姿态）。`live`＝用捕获的活姿势，仅供对照：活姿势与参考姿态最大差 180°（配件）/171°（手指）。 |
| `--hand-rest {live,bind}` | `live` | 手链（手骨+手指）的 rest 来源**自动选择**：两个候选各算一次最大修正量，取更小且 ≤90° 的那个（小吱实测：捕获 126° vs 参考 70° ⇒ 选参考姿态）。 |
| `--no-direction <substr,...>` | 空 | 额外的“跳过方向修正”骨名（逗号分隔）。 |
| `--no-sim <substr,...>` | 空 | 命中的配件骨**及其子树**不做弹簧模拟，改为输出一条**恒定轨道**（rest 局部旋转）：既刚性跟随父骨，又不会落进运行时对“无轨道骨”的处理（伊洛伊：`--no-sim headLine` 固定头上的环）。 |
| `--no-sim-names <name,...>` | 空 | **按精确骨名**固定（连子树），用于头环这类「只有几个角色有、关键词会误伤旁边头发」的硬件挂件。内置表 `HEAD_ORNAMENT_BONES` 默认生效（小吱 `Bn_m_headProp_001`；浔 `Bn_m_headProAa/Ab/Ac/B_001` 四件），新角色加进表里或用这个开关。 |
| `--no-sim-builtin {0,1}` | `1` | 0＝不套内置头饰名表，只认 `--no-sim` / `--no-sim-names`。 |
| `--track-untracked {0,1}` | `1` | 1＝**每一根骨都给轨道**：本来不会被驱动的骨（配件弹簧跳过叶子骨：发梢、耳环环）输出一条恒定轨道（参考姿态的局部旋转），刚性跟随父骨。0＝旧行为：这些骨完全没有轨道，运行时兜底会把它们钉在场景上（娜娜莉双马尾的发梢、伊洛伊的耳环）。用 `group_tracks.py` 检查有没有漏。 |
| `--sim-scale <substr=gain,...>` | 空 | 命中配件骨的**摆动幅度按比例缩小**：以该骨自己的参考姿态为锚，保持偏差轴、把角度乘 gain（1=不变，0.5=一半，0=刚性）。注意 `hairB_` 要带下划线才不会误伤 `hairBa_`。 |
| `--sim-swing-only <substr,...>` | 空 | 命中配件骨**只弯不拧**：保留弹簧给出的朝向（还会摆），但把它绕自身轴的拧固定在参考姿态上。这套 rig 的发丝弹簧弯 4–7°、却拧 27–44°，扁发片一拧就“原地打转”并刮过头穿模（伊洛伊：`--sim-swing-only hairF_,hairA_,hairB_`）。**发丝已自动应用这条规则**（见下一行），此开关留给命名不同的角色。可与 `--sim-scale` 叠用。 |
| `--no-swing-hair` | 关 | **关闭上面的发丝自动规则**，仅供 A/B 对照（开了之后发丝会连 roll 一起摆）。 |
| `--finger-roll {own,hand,world}` | `hand` | 手指 rest 的 roll 来源。**当前不影响输出**：手/手指/脚/趾整链被排除在方向修正之外（`mmd2bip.py` 的豁免分支先 `continue`），所以这段 roll 代码不可达——实测三种取值的输出**逐字节相同**（骨头 sha1 一致）。等哪天重新启用手指方向修正，这个开关才会说话。 |
| `--finger-twist <deg>` | 0 | 所有手指额外绕自身轴扭转，用于对照。 |
| `--finger-mapping {aligned,positional}` | `aligned` | `positional`＝旧的按序号映射，仅供对照。 |
| `--twist {0,1}` | 1 | 0＝不把肢体扭转分摊到 Twist 骨（Twist 骨是叶子节点，只影响肢体网格扭转）。 |
| `--ik-mode {follow,on,off}` | `follow` | `follow`＝跟随 VMD 的 IK 开关轨道；`on`＝忽略关闭记录；`off`＝完全跳过源 IK、只播放 FK。 |
| `--mapping SOURCE=TARGET` | 空 | 把剩余的未映射 VMD 轨道显式接到目标骨，可重复。`人差指`、全半角数字、四节手指和数字+`先` 指尖别名已自动识别；映射排在自动映射之后，目标骨已被自动映射时忽略。 |
| `--parent SOURCE=TARGET` | 空 | 把源轨作为额外父级插入目标骨，默认继承旋转，可重复。 |
| `--parent-position SOURCE=TARGET` | 关 | 为同一父级关系启用局部位移继承；常与 `--parent` 同用。 |
| `--parent-no-rotation SOURCE=TARGET` | 关 | 关闭该父级关系的旋转，只保留位移。 |
| `--parent-anchor SOURCE=TARGET=ANCHOR` | 原父级 | 指定目标骨架中的静止位置参考骨，用于旋转中心和位移坐标换算。 |
| `--control SOURCE=KIND,SIDE,FINGER,AXIS,GAIN[,PAIRED]` | 空 | 把源轨解释为手部控制。`KIND=grip/spread`，`SIDE=left/right/both`，`FINGER=all/thumb/index/middle/ring/pinky`，`AXIS=x/y/z`；第六项填 `paired` 或 `both` 时双手同步。 |
| `--arm-ik SOURCE=SIDE,GAIN,BEND[,BOTH][,FOLLOW]` | 空 | 把源轨位移解释为手腕目标。`GAIN` 为 `0.1..3`，`BEND` 为 `20..170` 度；附加 `BOTH` 双手同步、`FOLLOW` 跟随腕部朝向。 |
| `--ignore SOURCE` | 空 | 明确忽略源轨道，可重复。忽略优先级高于自动和手动映射。 |
| `--root-vertical <0..1>` | 1.0 | 根位移竖直分量缩放。**不要归零**：MMD 里中心升高正是腿推起来的结果，冻住它而腿仍动会让脚陷地。 |
| `--sim-*` | 见下 | 配件（头发/裙/飘带）的骨骼弹簧：`--sim-drape 0.15`、`--sim-damping 16`、`--sim-max-lag 25`、`--sim-inertia 0.5`、`--sim-stiffness 200`。 |

## 四条护栏（同一条原则：源数据不可信时不要强行对齐）

1. **修正量 > 90° 弃用**：该骨保留引擎参考姿态。MMD 的脚尖（`つま先`）是叶子骨且尾巴是朝前标记，
   修正量 119.7°，强行对齐会把脚尖往下拉 80°。
2. **手链豁免**：PMX 里四指尾巴全部写成沿 +X，方向完全相同（四指与中指夹角都是 33.4°）；把它们
   当基准会把目标骨架自己的扇形压平成一块板（“扳手手”）。手骨本身需要 76.3° 修正，强行对齐会把
   手腕弯向胸前。
3. **脚链豁免**：脚的方向定义为“指向脚趾”，而脚趾正是上面那根标记骨（本身 119.7° 已弃用），
   于是脚拿到 41° 的噪声修正、整个脚往上翘。对照组：大腿/小腿只有 0.3–4.3°，所以 41° 是噪声。
4. **配件骨不当方向参考**：一根骨的方向只从**解剖子骨**（`Bip001-*`）取；没有解剖子骨时，用“到达该骨
   的那段骨”（和自己的尾巴一样，即视作叶子），配件（`Bn_*`）永远不作数。九原的 `Bip001-Head` 底下
   全是头发/帽子/耳环，最长的一根头发 14.8 cm、朝右上前方；把它当成头的方向，就让头永久朝**右上方仰
   37°**（症状：“跳的时候脖子一直往右上方仰着”）。修正后 5.3°，与脖子同向。修正量 37° 低于 60° 的
   观察线，只有自检脚本的“方向来源”一列能看出来，光看修正量是发现不了的。

## 必须遵守的不变量

- **根位移必须转成目标坐标轴**再输出。漏转轴时 MMD 的前后轴（实测 53.1 cm）会被引擎当成竖直，
  角色表现为“悬空”，而真正的竖直（53.6 cm）跑到水平轴上。
- **cm/MMD 单位按“现场角色”的骨段长度换算**（`mmdLegLength` 写进文件，插件侧用运行时骨骼换算）：
  用导出角色的腿长会让另一个角色矮 24 cm。
- **配件骨不能被动作文件固定住**：未被动作驱动的骨在运行时坐在**引擎参考姿态**上，否则会永久
  保持“按下播放那一刻”的姿势（实测可差 180°，表现为裙子卡在掀起状态）。
- 插件播放动作时会把手链之外未驱动的骨也一并写入，因此**不要**指望游戏自身的布料/物理继续演算。
- **配件骨不是都要动**：耳环、角、戒指、光环这类“硬件”挂件被弹簧模拟会摆得很假（而且常常挂在会摆的链子
  末端：看不见的父骨一动，环就跟着飞）。这类用 `--no-sim` 固定（伊洛伊：`--no-sim headLine` 固定头上的环，
  同时羊耳 `Bn_*_ear` 保持模拟）。**固定 ≠ 不给轨道**：固定是输出一条恒定轨道，让运行时刚性跟随父骨。
- **发丝默认只弯不拧**（`SWING_HAIR_WORDS`：`hair`/`hairline`/`hari`/`kami`/`髪`/`かみ` 子串命中即算发丝，
  与角色命名无关；要关掉用 `--no-swing-hair`，仅供 A/B 对照）。实测：小吱前发 `Bn_m_hairF_001` 相对自身
  rest 的偏差最大 **179.7°**，其中 **100% 是绕自身轴的拧**；自动规则把它压到 **1.4°**，只剩摆动。
  副作用是「拧」被拿掉后摆动目标也变小（A/B 组发丝总偏差 60–100° → ~17°），头发整体更收敛；
  `--sim-scale` 只能缩小不能放大（gain 钳在 1.0），想要更大摆幅得改弹簧刚度/阻尼。
- **每一根骨都要有轨道**（`--track-untracked 1`，默认开）：配件弹簧靠“子偏移”判断骨朝哪边，**叶子骨**（发梢、
  耳环环、挂件末端）没有子偏移，弹簧直接跳过 → 以前这些骨一条轨道都没有，运行时的兜底会把它们**钉在场景上**
  （娜娜莉双马尾的发梢、伊洛伊的耳环都是这个）。现在给它们输出一条恒定轨道（参考姿态的局部旋转），
  刚性跟随父骨。判断办法：`python group_tracks.py <motion.json>` 看有没有 `untracked` 的骨。

## 自检脚本

```
python swing_table.py <skeleton.json>     # 各骨的 rest 修正量：>60° 就要怀疑方向参考
python direction_audit.py <skeleton.json> <pmx.json>   # 修正量 + 方向取自哪根子骨（配件骨/叶子会标出来）
python track_amplitude.py <motion.json>   # 每根骨的幅度：0.0° 表示它根本没动
python group_tracks.py <motion.json> [skeleton.json]   # 哪些骨没有轨道（会被运行时兜底）
python check_motion.py <motion.json> [skeleton.json]   # 结构、轨道数、骨名是否都在导出里
python bezier_sampler_check.py   # VMD 四通道 Bezier 解码与采样
```

自检脚本一律从本目录运行（`pmx.json`/`vmd.json` 是相对路径参数）。注意别在别处留一份旧的
`mmd2bip.py` 再让脚本导入它：转换跑的是哪一份，要认准 `--out` 那行打印出来的路径。
