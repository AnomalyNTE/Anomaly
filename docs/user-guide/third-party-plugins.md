# 第三方插件

Anomaly 可以直接从插件源下载、更新和卸载社区插件。平时不需要手动找 DLL，也不用把文件复制进游戏目录。

## 安装前先看一眼

第三方插件和内建插件一样，最终都会作为原生 DLL 在游戏进程里运行。Manifest 中的 capability 只限制它能调用哪些 Anomaly 服务，不是 Windows 安全沙箱。

> [!WARNING]
> 插件源由社区维护，Anomaly 不会替你审核插件。当前插件列表和 ZIP 包也没有发布者签名。HTTPS、包结构检查和 Manifest 校验能挡住损坏或放错的文件，但不能证明代码安全。只添加你信任的插件源，只安装你了解来源的插件。

安装前建议确认三件事：

- 作者和源码仓库是否可信，最近是否仍在维护。
- 插件说明是否说清用途，Manifest 申请的 capability 是否与用途相符。
- 插件是否支持当前 Anomaly Plugin API 和 `nte`。

## 下载并启用插件

1. 进入游戏后按 `Insert` 打开 Anomaly。
2. 打开 **Plugins > 可用**。页面会列出已启用插件源中的插件；不兼容的项目会显示原因，并禁用安装按钮。
3. 找到插件后点击 **安装**，等待状态变为成功。
4. 切到 **已安装**，选中刚安装的插件并启用。

新插件默认不会自动启用。这样可以先看清插件说明、状态和所需权限，再决定是否运行。

如果安装按钮是灰色的，通常是插件声明的游戏或 Plugin API 与当前 Runtime 不匹配。页面会显示具体原因。

> [!NOTE]
> 安装一个插件不会顺带下载它的必需依赖。启用后若状态提示缺少依赖，请回到 **可用**，把对应依赖也装上。

## 更新插件

插件源发布了更高版本后，它会出现在 **Plugins > 更新**：

1. 打开 **更新**，确认版本和来源。
2. 点击 **更新**，等待下载和安装完成。
3. 回到 **已安装** 查看运行状态；需要时可以手动重载。

更新时 Runtime 会先校验新包，再替换旧目录。下载、解压或校验失败时，现有插件不会被半个新包覆盖。

## 卸载插件

从插件源安装、并且仍能在 **可用** 目录中找到的插件，可以在 **已安装** 页的操作菜单或详情页卸载。卸载会删除插件包，但会保留 `Anomaly\config\plugins\<插件 ID>` 下的设置和 `Anomaly\state\plugins\<插件 ID>` 下的数据，重装后还能继续使用。

手动复制的插件，或者已经从插件源下架的插件，需要手动删除：

1. 退出游戏。
2. 删除对应的 `Anomaly\plugins\<插件目录>`。
3. 要把设置和数据也清掉时，再删除 `Anomaly\config\plugins\<插件 ID>` 和 `Anomaly\state\plugins\<插件 ID>`。

不确定目录属于哪个插件时，先打开目录里的 `manifest.json`，核对 `id` 和 `name`，不要按文件夹名字猜。

## 管理插件源

打开 **Plugins > 第三方插件** 可以管理插件源：

1. 打开“启用第三方插件”总开关。
2. 点击“添加插件源”，填入对方提供的 `pluginmaster.json` HTTPS 地址。
3. 勾选需要启用的来源，点击“应用”。
4. 回到 **可用**，点击右上角刷新按钮。

运行包会预置一个已启用的插件源。实际地址保存在 `Anomaly\plugin-repositories.json`，不要依赖文档里的固定链接。

每个插件源可以单独停用，停用后地址仍会保留。多个插件源出现相同插件 ID 时，目录只显示版本最高的一项，所以不要添加来历不明的源。

生产插件源和下载地址必须使用 HTTPS。`file://` 只留给插件作者做本地测试，普通使用不需要打开。配置文件的完整格式见[配置参考](configuration.md)。

## Anomaly 会检查什么

安装前会检查：

- 插件源和下载地址是否符合传输规则。
- ZIP 内是否有越界路径、重复目标或异常体积。
- ZIP 根目录是否直接包含 `manifest.json`。
- 列表中的插件 ID、版本是否与 Manifest 一致，列表和 Manifest 是否都支持当前游戏与 Plugin API。
- Manifest 指定的入口是否是包内可用的 DLL。

这些检查主要防止坏包和装错包，不是安全审计，也不会判断插件行为是否合适。

## 下载或刷新失败

先按这个顺序看：

1. 在 **第三方插件** 中确认总开关、对应插件源和 HTTPS 地址都正确。
2. 回到 **可用** 点击刷新。网络失败时，页面可能继续显示上一次成功获取的缓存列表。
3. 看页面给出的兼容性或安装失败原因。
4. 查看 `Anomaly\anomaly-platform.log` 中的下载、解压和 Manifest 错误。

仍然没有解决时，见[故障排查与 FAQ](troubleshooting.md#第三方插件下载与更新)。

## 给插件作者

要让自己的插件出现在 **可用** 页面，需要发布根目录结构正确的 ZIP，并维护一份 `pluginmaster.json`。完整流程见[发布第三方插件](../developer-guide/plugin-distribution.md)。
