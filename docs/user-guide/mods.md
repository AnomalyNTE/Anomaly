# 模组（Mods）

> 🌐 [English](../../en/user-guide/mods.md) · 简体中文

启动器的「模组」页用来管理游戏目录里的 pak 模组：看有哪些、开关、卸载、重命名、导入压缩包，以及打开「启用模组加载」所需的开关。

## 打开位置

启动器顶部模式栏：**代理安装 / 实时附加 / 模组**。点「模组」即可，不需要游戏在运行。

页面顶部显示实际使用的目录：

```
<游戏目录>\Client\WindowsNoEditor\HT\Content\Paks\~mods
```

> 目录随「客户端」切换（CN / Global）与游戏安装位置变化；启动器会自动推导，找不到时回退到 `~mods` 的默认位置。

## 能做什么

| 操作 | 说明 |
| --- | --- |
| 列表 | 每页 10 个模组，翻页按钮在列表上方；显示开关、封面、名称、文件数、占用、作者和版本，无封面时保留图片位置 |
| 启用 / 禁用 | 热加载模式保存选择并由 Runtime 挂载／卸载；兼容模式在游戏关闭时为容器文件加／去 `.disabled` |
| 启用开关 | 开启模组时自动关闭同车型模型或资源冲突的模组，与游戏内 Mod 管理同步 |
| 卸载 | 删除该模组的文件或文件夹 |
| 重命名 | 弹窗输入新名字，直接改磁盘上的名字 |
| 导入压缩包 | 选择 ZIP、7z 或 RAR 压缩包，自动解压并把 `.pak/.utoc/.ucas/mod.json` 放进 `~mods\<压缩包名>\` |
| 搜索 | 按显示名、目录名、作者模糊匹配 |
| 过滤 | 全部 / 已启用 / 已禁用标签栏；切换标签或搜索时回到第一页 |
| 来源 | `mod.json` 里有链接时多一个按钮，用浏览器打开 |
| 分组/备注 | 可为未分组模组设置分类；散装文件使用同名 `.mod-notes.json` 保存 |

**是否要重启取决于运行时加载有没有启用**：未启用时 pak 只在启动时挂载，改动要重启游戏；启用后
可以在游戏运行中增删容器，热替换按「释放 → 覆盖 → 重挂」做，详见下方
[运行时加载与热替换](#运行时加载与热替换)。

## 目录与文件约定

```
Paks\~mods\
  Mint CSU Prodigy Black\        ← 一个模组一个文件夹（推荐）
    mod.json
    xxx_P.pak
    xxx_P.utoc
    xxx_P.ucas
  SomeOldMod_P.pak               ← 也支持散装文件，按基名自动归组
  SomeOldMod_P.utoc
  SomeOldMod_P.ucas
```

- 支持扩展名：`.pak`、`.utoc`、`.ucas`（IoStore 模组通常是三件套）。散装容器保留完整基名，`foo` 与 `foo_P` 是不同模组。
- 禁用标记：文件名或文件夹名结尾加 `.disabled`。
- `~mods` 的挂载优先级高于游戏自带的 `pakchunk*`，所以放在这里才会覆盖原版资源。

`mod.json`（可选）字段：

```json
{
  "name": "显示名称",
  "version": "1.0",
  "author": "作者",
  "modLink": "https://gamebanana.com/mods/xxxxx"
}
```

## 启用模组加载

页面上的开关读写 `Anomaly\config\pak-mods.json` 的 `enabled`，默认开启。热加载支持代理启动、
启动时注入和运行中附加三条入口；活动 Profile 必须通过 `ue5.pak` 的符号、ABI 和布局校验。

- 三种入口和游戏内 Mod 管理插件统一使用游戏 `Binaries\Win64\Anomaly\config\pak-mods.json`。
- 该文件尚不存在时读取旧 Runtime 目录的配置；首次保存后以游戏目录为准。
- Launcher 和插件对同一文件加互斥锁，重新读取后原子保存，保留手工指定的 `mods` 数组等其他字段。
- 配置损坏时保存报错；Runtime 保留现有挂载并在状态里报告 `lastError`。

```json
{ "schemaVersion": 1, "enabled": true, "mode": "hot",
  "modStates": { "OldVehicle/": false, "NewVehicle/": true, "Sound.pak": true } }
```

`modStates` 的目录 key 以 `/` 结尾，散装容器用相对 `.pak` 文件名。它同时过滤目录扫描和手工
`mods` 清单。热加载禁用不改名已挂载文件，因此游戏运行时也可操作，重新启用同一份文件会重新挂载。

**兼容模式**将 `mode` 设为 `compatibility`，使用之前的代理启动签名绕过，由游戏自行扫描和加载。
请关闭游戏后切换模式，并通过代理启动。此模式不会安装热加载缓存 Hook，也不执行 Runtime 的
挂载、卸载或预读命令；修改启用状态需要重启。切换时会转换 `.disabled` 标记并保留当前选择。
模式固定到游戏进程结束，不能仅停止并重启 Runtime 来换模式。

兼容开关保留并启用已有的 `pak-signature-bypass.json` 配方；没有签名配方时保存失败，不会猜测签名。
热加载模式不启动这条旧路径。`pattern` 必须唯一命中，`jumpOffset` 指向 E8/E9 跳转。
兼容的 `patchBytes: "B0 01 C3"`
表示直接 Hook 对应的布尔谓词，其他原始补丁字节不再接受。`verifiedFor` 仅作记录，不参与兼容判断。

## 运行时加载与热替换

Runtime 默认每 750 ms 扫描 `Paks\~mods`，跳过 `.disabled` 文件夹、文件和 reparse 条目。
每个 `.pak` 是一个容器，默认读序从 **100000** 递增；相同资源路径按引擎的读序规则选择。
默认 id 是去掉扩展名后的相对路径，例如 `Outfit/Shared`，不同文件夹下同名 pak 不会互相覆盖状态。

可用清单固定挂载集合：

```json
{ "schemaVersion": 1, "enabled": true,
  "mods": [ "MyMod\\MyMod.pak", { "id": "Sound", "pak": "Sound.pak", "order": 100100 } ] }
```

相对路径按 `Paks\~mods` 解析。有 `mods` 数组时以清单为准；没有时扫描目录。
`enabled: false` 停止自动挂载并尝试卸载本 Runtime 管理的容器。配置格式错误、清单文件缺失或重复 id/路径
不会被当成空集合。卸载失败的条目继续保留，并阻止本轮新挂载，避免不同 id 的两个替换版本同时生效。
每轮还会在引擎挂载锁内复制实际文件名，卸载 `~mods` 中未由当前 Runtime 持有的启动挂载，
再按选择重新挂载。原生卸载使用引擎保存的原始文件名，避免相对路径导致旧包残留或禁用失效。

```text
anomaly-cli --pid <游戏 PID> pak status
anomaly-cli --pid <游戏 PID> pak release "My Mod/MyMod"
anomaly-cli --pid <游戏 PID> pak reload
anomaly-cli --pid <游戏 PID> pak mount "My Mod/MyMod.pak" 100100
anomaly-cli --pid <游戏 PID> pak unmountall
```

- `release` 成功后保持 `released`，直到 `.pak/.utoc/.ucas/.sig` 的时间戳或大小发生变化。
  `unmountall` 同样不会在下一次扫描立即重挂。需要重新挂载同一份文件时可显式使用 `mount`。
- 手动 `mount` 仍受后续清单/目录扫描约束；要持续保留外部路径，应把它加入清单。
- **卸载成功不等于所有文件句柄已关闭**。UE 可能保留异步读请求和已打开的资源句柄，文件仍被占用时
  不能强制覆盖。等待读取完成，必要时退出游戏后替换。
- **多文件容器不能逐个边复制边挂载**。替换时先关闭自动加载或使用清单暂时移除该条目，把完整文件集
  准备到监视目录之外或 `.disabled` 目录，再放到最终路径并恢复配置。轮询不提供多文件事务，
  相同时间戳和大小也不能识别内容变化。分卷或可选容器的更新应使用这个完整停用/启用流程。

状态写入 `Anomaly\state\pak-mods.json`；`diagnostics-summary.json` 的 `pakMods` 节点也包含快照。
`mode` 表示进程采用的加载路线，`pid` 用于识别所属进程；`residentAssetsReloaded: false` 明确表示
容器切换没有主动刷新驻留资产。

### 内存调用与诊断边界

挂载前先验证 Profile，再获取 `FPakPlatformFile`，安装缓存校验路由、配置签名支持，最后调用引擎的
`Mount(FPakMountArgs, FIoStatus, FPakListEntry)`。纯 `.pak` 使用 `SkipContainerFile`；有 `.utoc` 时
交给引擎加载同名 IoStore 容器，文件大小不用于猜测包类型。挂载输出持有一个强引用，由 Runtime
在卸载或停止时释放。签名支持的任一步失败都会阻止新挂载。

缓存 Hook 在引擎缓存锁内读取请求归属：签名表存在时调用原校验器；确认空表时调用原生完成函数，
让引擎取得读结果并处理队列和计数；读取失败时仍走原函数。Hook 不手工转移请求中的缓冲区。
Runtime 停止后断开并等待诊断 sink；Core 仍驻留，缓存路由继续服务可能迟到的原生 I/O。
同一进程重启 Runtime 时复用先前验证的 Pak 绑定，避免已安装的补丁影响重新扫描。

签名表来自 `.sig`，**预读不会生成缺失的签名表**。挂载不自动预读或运行全局索引整理。
显式执行 `pak prime "<id>"` 可以探测一个本容器文件，返回 `stage` 和读取结果；这不是修复命令，
也不能证明所有资源可加载。IoStore-only 容器没有可供该 pak 读取路径探测的数据，也不等于挂载失败。

这些路径会改变进程级签名检查。关闭自动加载或停止 Runtime 不保证恢复全部签名状态；
完整恢复以重启游戏为准。符号或布局失配时功能降级，不继续猜测地址。

### 资源热加载的范围

这里管理的是容器挂载集合。卸载不会自动销毁已经加载的 `UObject` / `UPackage`，也不会自动重建
Asset Registry、刷新材质/音频或替换驻留资源。不要把 `mounted` 理解为所有现有资源已热更新。
已有资源、异步加载中的容器和完整替换效果仍需要游戏内验证；需要确定使用全新资源时重启游戏。

独立的 **Mod 管理** 插件和 Launcher 读取 `.pak` / `.utoc` 目录索引，按内部资源路径自动分类。
角色按完整皮肤目录分组，例如零的普通服装为 `Player_051_female`、泳装为 `Player_051_female_swimsuit`；
黑羽普通形态与变身形态分别归类。优先采用皮肤模型所属目录，附带的公共材质和变体辅助资源不增加皮肤分组；
只有贴图替换时按贴图所属目录分类。奶蛋替换乌鸫使用 `Pendant_07`，借用贴图的文件名不会改变归属。
其他资源按内容目录分组，例如音频为 `/game/wwiseaudio`；索引无法读取时保留未分类状态。
分类本身不增加互斥，同角色但资源不重叠的模组仍可共存；资源清理按钮仅用于载具。
GT3 RS 与 P1 都覆盖 `Vehicle_037`，Tourbillon 覆盖 `Vehicle_026`。覆盖相同资源，或替换同一车型
车身/蓝图的 mod 互斥；启用其中一个会同时保存关闭冲突项的选择。IoStore 按资源路径和 chunk ID 检查，
内容哈希与长度相同的公共资源可以共存；内容不同或无法确认相同时仍互斥。读取索引元数据，不扫描大资源文件。
加密、缺少目录索引或不支持的格式显示分析不完整；不会凭压缩包或模组目录名称猜分类。插件和 Launcher 共用解析与选择逻辑。
手工配置若启用了已知冲突项，Runtime 仅暂停冲突 Mod 的挂载变化并保留其原挂载，其他 Mod 继续同步和热替换。
冲突项列在状态文件的 `conflicts` 中，重新选择一个变体后解除暂停。

P1 示例 ZIP 内的轮毂选项是替代版本，应只导入一套 `.pak/.utoc/.ucas`。同一 mod 目录内的多个容器
视为一个整体，不能替你从目录内部选择轮毂版本。

列表每页显示 10 个模组，翻页按钮位于列表上方。

1. 在独立的「Mod 管理」插件窗口确认热加载模式，通过互斥开关切换 Mod，与 Launcher 同步。
2. 容器切换完成后自动尝试释放同车型所有变体的资源；每个车型分组保留一个「释放资源」按钮用于手动重试。
3. 若仍有车型实例，可以下车后点击该分组唯一的「强制清理」按钮。它校验 UObject 序列号、类型和所属世界，
   拒绝玩家当前乘坐的车辆，调用游戏的 `HTWheeledVehicleDrivable.SafeDestroyVehicle`，同时回收 Mass 车辆实体。
   此按钮只清车辆，不单独释放资源；如果之前的 Mod 切换因车辆存在而暂停，清车完成后续接一次资源释放。
4. 资源释放会先让目标车型的旧物理模板查找键失效，再释放共享参数，避免 GC 后召唤访问旧类地址。
   随后调用 `HTGameUserSettings.ClearCacheUIAndGC`，等待后续 GC 并检查原资源是否仍驻留。
5. 重新召唤检查模型。「部分释放，仍驻留」表示仍有旧资源存在，不代表整个 Mod 切换失败；共享数据表
   `DT_vehicleModuleData` 不继续强制释放，其内容也不保证在本次切换中更新。同路径新加载的资源不算旧资源残留。

清理使用经过 Profile 与反射校验的布局和引擎调用，不修改 UObject 垃圾回收标记。
失效的物理模板内存保留至场景销毁，由引擎回收，避免破坏其他缓存中的借用指针。
它会清理共用资产/UI 缓存，可能短暂停顿或重建界面。容器索引不描述所有跨包引用，资源被其他系统保留时
仍需切换场景或重启游戏；尚未完成 GT3/P1 实机切换验证。
插件报告进程启动时确定的实际模式。兼容模式下禁用热切换、资源清理和强制清理入口，需要退出游戏后在 Launcher 修改。
此功能新增宿主服务，旧 Core 需随构建产物一起更新并重启游戏；仅热重载插件不能补齐旧 Core 的接口。

## 排障

| 现象 | 先看什么 |
| --- | --- |
| 模组不生效 | `pak status` 的 `available`、`state`、`lastError`，以及 `pak_mods.mount_failed` 的引擎原因 |
| 列表为空 | 目录路径、`.disabled` 标记和清单的 `mods` 数组 |
| 不能覆盖/禁用文件 | 容器是否已释放，是否仍有引擎读请求；文件被占用时先退出游戏 |
| 挂载成功但资源没变 | 是否为已驻留资源；挂载不会主动刷新它们 |
| 读取失败 | 缓存 Hook 是否可用，Profile 是否匹配，文件集是否完整；`pak prime` 只用于诊断 |
| 导入压缩包失败 | 压缩包是否完整、是否加密；查看解压报错 |

## 浏览与在线安装

启动器第四个页签「浏览」直接对接 GameBanana 上的 Neverness To Everness 模组（游戏 id `23012`）。

| 操作 | 说明 |
| --- | --- |
| 搜索 | 输入时即时筛选已加载模组，按名称和作者匹配 |
| 留空浏览 | 关键词留空时浏览该游戏的最新模组 |
| 自动加载 | 首次打开下载页时自动请求前 15 个模组 |
| 刷新列表 | 重新请求第一页，成功后替换列表；加载中或失败时保留已有列表 |
| 加载更多 | 每次追加一页（服务端固定 15 条/页） |
| 排序 | 液态玻璃标签栏：名称 / 下载量 / 大小 / 时间，再点同一标签切换升降序 |
| 缩略图 | 列表左侧 120×68 预览；鼠标悬停显示 530px 大图（首次悬停才下载，之后走缓存） |
| 页面 | 用浏览器打开该模组的 GameBanana 页面 |
| 已安装 | 已通过本启动器安装过的模组会显示「已安装」，按钮变为「重装」 |

安装流程：取文件地址（`ProfilePage` 没有 `_aFiles` 时自动改用 `/Mod/<id>/Files`）→ 下载 → 按内容识别 ZIP / 7z / RAR / RAR5（内置解码，无需安装 7-Zip）→ 解压 → **整棵树复制**到 `~mods\<模组名>\` → 把封面写成 `icon.png` → 写入 `anomaly-source.json`。

解压使用独立临时目录，失败或结束后自动清理；支持中文路径，拒绝路径越界、链接、重复文件及加密包，上限为 16 GiB / 20000 项。下载页的取消按钮也会取消解压

网络：优先使用系统代理（本机实测走代理约 5 MB/s、直连约 14 KB/s），代理不可用时回退直连；下载失败会再尝试 `curl.exe`。失败原因写在 `Anomaly\logs\launcher-update.log`。

> 版本变慢或卡住时先看这个日志：`dl: total timeout`、`dl: stalled after N bytes`、`install: WinHTTP failed, trying curl`。

## 支持的资源模组

| 类型 | 形态 | 能否在本框架生效 |
| --- | --- | --- |
| 资源替换 | `.pak/.utoc/.ucas` 三件套 | ✅ 引擎直接挂载，配合「启用模组加载」即可 |
| 资源 + 配套文件 | 三件套 + 图片/脚本目录（如加载页替换：pak + 45 张 jpg） | ⚠️ pak 能挂上，但配套资源需要对应工具读取（例如 NTEUiSwap Plus），否则看不到效果 |

安装时检查压缩包中的 pak/utoc/ucas 文件，缺少这些资源文件时提示无法加载

## 更新检查与在线更新

- 「检查更新」只读取每个模组目录里的 `anomaly-source.json`，格式为 `schemaVersion: 1`、`provider: "gamebanana"`，以及 `modId`、`fileId`、`fileName`、`fileMd5`、`author` 和 `displayName`；两个 ID 均保存为字符串。
- 判定：`fileId` 变化 **或** `fileMd5` 变化即视为有新版本；没有来源记录的模组不做跟踪。
- 首次登记：模组 `mod.json` 里有 `modLink` 时，第一次检查会把当前最新文件记为基线。
- 有新版本时该行出现 `↑ 新版本 vX` 与「更新」按钮，点击后下载并替换文件、保留 `icon.png`。
## 界面偏好

启动器会记住这些选择（存在 `<启动器>\\Anomaly\\config\\launcher-prefs.json`）：

| 键 | 含义 |
| --- | --- |
| `browseSort` | 下载页的全量排序（`default` / `new` / `downloads` / `views` / `likes`） |
| `browseCategory` | 选中的分类 id（空 = 全部分类） |
| `hideMature` | 「隐藏 NSFW」开关状态，默认开启 |

## 能力边界（都由 GameBanana 接口决定）

| 想做的事 | 接口现实 | 我们的做法 |
| --- | --- | --- |
| 按下载量/浏览/喜爱全量排序 | 只有 `apiv13/Mod/Index` 支持（`Generic_MostDownloaded` / `MostViewed` / `MostLiked` / `Newest`） | 走该接口，选排序即重新拉第一页 |
| 关键词筛选 + 排序 / 分类 | 输入栏只筛选已加载列表 | 保留当前排序和分类，无额外搜索请求 |
| 列表里显示下载量 | 列表接口不返回 `_nDownloadCount` | 逐 mod 从 `/Mod/<id>/Files` 取（和文件大小同一次请求） |
| 分类筛选 | `_aFilters[Generic_Category]` 只认**数字 id** | 从记录的分类 URL（`…/cats/43029`）取 id |
| NSFW 过滤 | NTE 的记录里只有 `_bHasContentRatings` 被填 | 本地过滤；`_bHasNsfwContent`/`_bIsNsfw`/分类名含 NSFW 也一并判定 |

## 已知限制

- **游戏运行时**可以导入和下载；热加载模式可以切换模组。已禁用的模组可更新、改名和卸载；若文件仍被引擎占用，等待释放后重试。兼容模式不能热切换，新导入项保持禁用，退出游戏后再启用。
- 导入和更新期间先关闭目标选择，完整复制容器文件后再恢复选择；失败时保持禁用。
- 没启用运行时加载时，改动要重启才生效（pak 只在启动时挂载）；启用后见
  [运行时加载与热替换](#运行时加载与热替换)。
- 启动器只挂载资源容器，不执行模组附带的 Lua 脚本

## 关于 RE-UE4SS（实验记录）

我们试过用插件在 `game-ready` 阶段加载 `ue4ss\UE4SS.dll`（官方实验版，`MinorVersion=6` 可认 UE5.6，Lua mod 能跑，实测 `NTENoTraffic` 生效）。但**只要 UE4SS 驻留进程，框架热键就明显失灵**，关掉多数 hook 与内置按键 mod 也无法消除。因此当前版本不启用该方案，相关文件已移出游戏目录。
