# BetterPose 姿态库与动作库设计

## 状态

待用户审阅。本文只定义方案，不包含实现代码。

## 目标

为 BetterPose 增加两个本地库：

- 姿态库：保存并快速应用当前骨骼姿势、身体偏移和表情。
- 动作库：保存并快速加载 BetterPose 自己的关键帧轨道。

MMD/VMD 动作不进入动作库。现有的文件导入/导出继续保留，用于交换文件；库用于快速保存和调用。

## 用户界面

新增「库」页签，内部提供「姿态库」和「动作库」两个区域。

### 姿态库

- 输入名称，点击「保存当前姿态」。
- 列表显示已保存条目，点击条目立即应用。
- 支持重命名和删除。
- 应用姿态时同时恢复骨骼姿势、身体偏移和表情。
- 应用作为一次统一编辑，进入现有的姿势/表情/关键帧统一撤销历史。

### 动作库

- 保存当前关键帧轨道并输入名称。
- 列表点击后加载关键帧轨道。
- 加载后停在起始帧，不自动播放。
- 支持重命名和删除。
- 用库动作替换当前轨道前需要确认；替换本身进入统一撤销历史。
- 动作库只接受 BetterPose 关键帧数据，不收 VMD、转换后的 MMD JSON 或镜头 VMD。

### 第一版明确不做

- 搜索、分类、标签。
- 姿态缩略图或角色截图。
- 部分套用（只套手、上半身等）。
- MMD/VMD 文件收藏或动作库缓存。
- 跨角色自动重定向动作。

## 存储

使用宿主提供的 BetterPose 专属持久状态目录，不把用户库文件写到 DLL 所在的插件包目录，避免保存文件触发插件热重载。

目录逻辑如下：

```text
<BetterPose state directory>/library/
  poses/
    <stable-entry-id>.json
  motions/
    <stable-entry-id>.json
  index.json
```

`index.json` 保存条目 ID、显示名称、类型和格式版本。实际文档使用独立文件，避免每次改一个条目都重写整个库。

文件名只使用稳定 ID，不使用用户名称，避免名称包含非法 Windows 路径字符或重命名导致引用问题。显示名称保存在索引中，并限制长度。

姿态文件使用现有 `betterpose-expression`/姿势文档的兼容数据结构扩展，至少包含：

- 格式和版本。
- 按骨骼名称保存的姿势角度。
- 根偏移。
- 表情值。

动作文件使用现有 `betterpose-keyframes` v1 轨道数据结构，不复制另一套关键帧格式。

## 数据流与线程

面板线程只产生请求，不直接进行文件 I/O，也不直接修改运行中的姿势或轨道。

1. 面板读取缓存的库索引并绘制列表。
2. 保存、应用、重命名、删除和覆盖确认转换为请求。
3. 游戏线程或受宿主允许的后台任务执行状态快照、文件读写和解析。
4. 应用请求回到游戏线程，写入姿势、表情或关键帧状态。
5. 成功应用后刷新统一编辑历史，并更新面板状态、条目列表和错误信息。
6. 文件写入使用临时内容加宿主存储服务的原子写接口；索引更新最后提交。

库索引加载失败时保留空列表并显示错误，不影响 BetterPose 其他页面。单个损坏条目不阻止其他条目加载；列表中显示该条目不可用，删除仍可用。

## 应用与撤销语义

### 姿态

保存时捕获当前骨骼角度、根偏移和表情状态。应用时按骨骼名称匹配当前角色，未匹配的骨骼报告数量但不使整个应用失败。应用完成后作为一个统一编辑状态进入历史，因此一次 Ctrl+Z 恢复应用前的姿势、表情和根偏移。

### 动作

保存时复制当前关键帧轨道。应用时先确认是否替换当前轨道；确认后替换轨道，停止关键帧播放并将播放头置为轨道起点。应用动作不自动播放。替换操作进入统一编辑历史，Ctrl+Z 可恢复替换前的轨道。

播放中的动作和 MMD 驱动状态不作为编辑记录。

## 名称与确认

- 名称不能为空，去掉首尾空白后保存。
- 同一库中重名时明确询问是否覆盖，不静默覆盖。
- 删除条目必须确认。
- 替换当前关键帧轨道必须确认；当前轨道为空时不需要确认。
- 错误显示在库页状态区域，不弹阻塞式异常窗口。

## 兼容与限制

- 现有独立姿势 JSON、关键帧 JSON 导入/导出保持原行为。
- 库文件不承诺被其他插件读取；格式中保留 format/version，未来可迁移。
- 库不保存 MMD 文件路径，不改变 MMD 加载、转换或音乐自动配对逻辑。
- 库目录由宿主状态服务管理；插件不能依赖扫描宿主内部目录来发现文件，索引是唯一目录清单。

## 验证

实现阶段至少覆盖：

- 新建、读取、重命名、删除姿态条目。
- 姿态保存并重新加载后骨骼、根偏移和表情一致。
- 姿态应用作为一次统一撤销，可完整恢复应用前状态。
- 新建、读取、重命名、删除动作条目。
- 动作应用替换当前轨道、停在起始帧且不自动播放。
- 动作替换可由统一撤销恢复。
- 重复名称、空名称、损坏索引、损坏条目和部分骨骼不匹配的错误处理。
- 插件默认构建和已有 BetterPose fixture 不受影响。
- 运行中保存库不会触发 BetterPose 插件热重载。
